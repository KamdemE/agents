## 1. Mail Tooling Workspace

### Goal
Design a mail workspace with clean separation:

| Layer | Role |
|-------|------|
| `mail-cli` | Complete human-facing command surface |
| `mail-mcp` | Compact agent-facing transport |
| `mail-admin` | Credentials, bootstrap, health, diagnostics |
| `mail-skill` | Hot instructions, templates, aliases, usage policy |

### Core Principles
- MCP should stay small and stable (prefer one validated `execute` tool over large catalog)
- Skill should stay editable and descriptive
- CLI should stay complete
- Admin layer should stay secret-aware but not model-facing

### Recommended MCP Shape
Suggested payload: `action`, `account`, `args`, `dry_run`. Optional: `help`, `auth_status`.

### Secret Handling (Critical Rule)
Secrets must **never** pass through the skill prompt. Instead:
1. Agent expresses intent
2. Local runtime resolves account
3. Resolver reads secret source of truth
4. Mail engine executes action
5. Response masked before returning

### Why This Works
Lower token usage, better validation, easier to evolve skill without touching engine, easier to keep CLI and MCP behavior aligned.

### Open Questions
- Single source of truth for credentials?
- Structured payloads only or also tiny DSL?
- Standard account aliases across mail, LinkedIn, WhatsApp?
- Template/contact sharing between skill and CLI?

## 2. WhatsApp Central Auth (`wa-core`)

### Problem
- `whats-mcp` uses Baileys auth files under `WHATSAPP_STATE_DIR`
- Multiple independent clients → reconnect churn and operational drift
- Edge WhatsApp Web stores IndexedDB — not a stable auth backend for Baileys

### Target Architecture

**`wa-core` service (docker-host):**
- Owns: auth directory, message store snapshot, connection lifecycle/reconnect strategy
- Persistent volume: `/data/state` as source of truth

**`whats-mcp-http`:** Front-end API on top of `wa-core`, consumed by agents over network (Tailscale).

**`whats-mcp-stdio`:** Local fallback client mode. Can target same canonical state path on host. Explicit degraded-mode notice when not reachable.

**`wa-bot` adjustment:** Remove private `auth_info` ownership, consume `wa-core` capability.

### Fallback Strategy
Edge remains fallback for manual recovery only — do NOT treat Edge storage as continuous primary auth backend.

### Next Steps
1. Create dedicated `wa-core` compose service
2. Bind all WhatsApp automations to this core
3. Add health dashboard (state, reconnect attempts, last disconnect code)
4. Define runbook: reconnect, re-auth, rollback, edge fallback

## 3. Microsoft Edge Agent Automation

### Goal
Visible Edge session for human-in-the-loop agent work: KπX and observers see the real browser; agents drive via MCP/CDP. Minimize repeated logins.

### Constraint (Chrome/Edge 136+)
Remote debugging cannot target the Default profile. Use a dedicated `user-data-dir`, log in once.

### Stack

| Piece | Choice |
|-------|--------|
| Browser | Edge headed, `--remote-debugging-port=9222` |
| Profile | `$HOME/.config/kpihx-edge-automation` |
| Launcher | `$HOME/.agents/skills/k-browser/scripts/edge-agent.sh` |
| MCP | `@agent-infra/mcp-server-browser` (attach) + `@playwright/mcp` |
| Fast IDE demos | `cursor-ide-browser` (isolated) |

### Setup Completed
- `.kshrc` → `edge-agent`, `edge-agent-status`
- `$HOME/.cursor/mcp.json` → both MCPs configured (CDP :9222)
- Docs: `k-browser/references/edge-cdp-setup.md`

### Remaining (KπX once)
- Run `edge-agent` and sign in to required sites in automation profile
- Reload Cursor MCP servers after first config read

### Not in Scope
- Cookie sync from Default profile (fragile, blocked by policy)
- systemd auto-start (optional)

## 4. Sovereign Tutorial Automation

### Problem
KπX builds a sovereign control plane (phone → PC, CLI beats narrow MCPs). Explaining it on camera is high friction. Goal: repeatable high-quality tutorials generated by agents with minimal human screen time.

### What's Already Extraordinary

| Layer | What We Proved |
|-------|----------------|
| **Phone → PC** | Termux + Tailscale + `ubuntu` → PC tmux + full shell |
| **Agents** | Same CLIs as desktop, launched from phone, no vendor lock-in |
| **Integrations** | Meta, LinkedIn, WhatsApp, X, mail, TickTick |
| **Cost model** | Tailscale + Termux + self-hosted — no per-seat cloud dispatch |

### Automation Tiers

| Tier | Output | Automatability |
|------|--------|----------------|
| **A — Article** | Docsify / techskills / GitHub Pages (MD from session log + QMD) | High |
| **B — Visual static** | Napkin SVG, PPTX (k-pptx) — text → diagram | High |
| **C — Terminal cinema** | MP4/GIF of real commands via VHS/asciinema | High |
| **D — Composed video** | Branded explainer (Remotion + TTS + clips) | Medium |
| **E — Publish** | YouTube / X / LinkedIn via k-media | Medium |

**Do not start with E.** Prove C → A → D on one story (e.g. `ssh s25` → `ubuntu` → `agent -p`).

### Video Without Face

| Technique | Tool | Best for |
|-----------|------|----------|
| Scripted terminal recording | VHS (`.tape` files), asciinema | SSH, tmux, CLI demos |
| Programmatic motion | Remotion (React) | Intros, diagrams, captions |
| Voice | edge-tts (already in toolchain) | Narration without mic |
| Diagrams | k-napkin | Architecture slides |
| B-roll (optional) | WebTop / Edge CDP | DOM demos |

### Pipeline

```
Storyboard (MD/YAML, agent-authored)
  → VHS tape run (terminal truth)
  → Remotion compose (brand, chapters, napkin, TTS)
  → ffmpeg finalize (1080p60, captions)
  → k-media publish (optional)
```

Human role: **approve storyboard + voice script** — not operate UI per frame.

### First Canonical Tutorial (MVP)

**Title:** *Control your PC agents from your phone (no subscription dispatch)*

**Acts (60-90s):**
1. Phone Termux — Tailscale connected (diagram)
2. `vhs`: `ssh s25` → shell on phone
3. `vhs`: `ubuntu` → PC tmux attach
4. `vhs`: `agent -p "summarize inbox"` or CLI one-liner
5. Napkin: stack diagram (phone → TS → PC → CLI)
6. Outro card: links to homelab docs

### Agent Division of Labor

| Role | Input → Output |
|------|----------------|
| Architect | Brainstorm + facts → `storyboard.md` |
| Scripter | storyboard → `*.tape` (VHS), test commands in tmux |
| Renderer | tape + assets → terminal MP4 |
| Composer | Remotion project → final MP4 |
| Publisher | final + metadata → techskills article + YouTube draft |

### Quality Bar
- 1080p, JetBrains Mono, dark theme aligned with KπX IDE palette
- Captions burned-in (FR/EN) from script
- Commands copy-paste true (CI-verified where possible)
- No real secrets in tapes (placeholders, `bw-env` mentioned not shown)

### Phases

| Phase | Deliverable | When |
|-------|-------------|------|
| 0 | This vision + 1 storyboard | Now |
| 1 | `demo.tape` + raw terminal MP4 | 1 session |
| 2 | Article in techskills + homelab presentation | Same week |
| 3 | Remotion wrapper + TTS | After MVP validated |
| 4 | Catalog series | Ongoing |
