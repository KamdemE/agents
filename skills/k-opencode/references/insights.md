- **2026-09-01 — opencode.jsonc `*.env → deny` glob does NOT protect bash commands (root cause of `cat .env` bypass):** The permission system matches file globs for `edit` and `read` tools (where the pattern matches the file path), but for `bash` the pattern matches the **command string** — so `"*.env": "deny"` in bash never fires because a bash command starts with `cat`/`less`/`head`, not `*.env`. The real fix is a `tool.execute.before` hook in `raw-exec-guard.js` that scans the command for file-path-like references matching `*.env*` (paths containing `/` or starting with `~/` or `./`) while excluding `*.env.example*`. Pattern: `/(?:(?:^|\s)(?:[~/.][^\s]*\/[^\s]*\.env(?![\w.]*example)[^\s]*))/` — negative lookahead excludes `.env.example*`, path anchoring avoids false positives on env var names (`MY_ENV=1`). 48/48 tests pass (10 `.env` blocked, 3 `.env.example` allowed, 6 env var/non-path allowed, 1 tmux send-keys exempt). Anti-repeat: when a glob `"*.env": "deny"` appears in opencode.jsonc's bash section, it is DEAD CODE — always add a hook-based guard for bash-level file access protection.

 - **2026-08-16 — Stateful tmux→agent notification hook (`tmux-notify.js`) — 3 hard-won Node/opencode lessons:** (1) **Reliable persistent-pane completion detection requires shell-side `precmd` (zsh) / `PROMPT_COMMAND` (bash) hooks, NOT tmux silence heuristics.** `monitor-silence` fires on any silent wait (including waiting for a `sudo` password), generating false positives. By hook-wiring the shell's prompt redraw event in `.kshrc` (propagated to all infras), we write a `{"event":"prompt","pane","ts"}` token directly to `/tmp/tmux-pane-done.log` only when the shell is actually back. Panes stay alive — no `remain-on-exit`, no `bind K kill-pane`, and no tmux-side hook triggers. (2) **A background watcher must be a RECURSIVE `setTimeout().unref()`, NOT `tail -F` and NOT `setInterval().unref()`.** A spawned `tail -F` keeps the opencode process alive forever (its readable stdout stream stays referenced even with `child.unref()`), hanging `opencode run` on exit. And `setInterval().unref()` re-references itself on every fire, so once it starts polling it also hangs the process. Only `setTimeout()` re-arming itself with `.unref()` on each iteration stays unreferenced across fires. (3) **`client.session.prompt` requires `body.agent`** — without it opencode may ignore the injected prompt (same requirement as `stop-enforcer.js`); resolve the agent via `client.session.messages()` + `agent-scope.currentAgent()`.
