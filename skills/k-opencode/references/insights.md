## Insights

- **2026-05-30 — Terminal-as-Consciousness:** Agent can observe and act upon itself using `tmux send-keys` (effector) + `capture-pane` (sensor). This enables a closed proprioceptive loop: write → capture → read → process → write. Full exploration documented in `references/terminal-consciousness.md`. Key practical finding: opencode requires double Enter (`Enter Enter`) via `send-keys` to submit queued text as a message.
- Initial baseline created automatically from insights governance standard.
- OpenCode install script can add PATH in `.zshrc`, but KπX runtime needs `.kshrc` as source of truth for cross-agent shell consistency.
- OpenCode `mcp` local servers require `type: "local"` and a `command` array (not `command`/`args` object shape used by some other runtimes).
- Browser automation MCPs in OpenCode should use local server ids `browser` and `playwright` with commands `browser-mcp-stdio` / `playwright-mcp-stdio` for parity with KπX runtime docs.
- OpenClaw secrets model: `openclaw.json` uses `{env:VAR_NAME}` refs; `models.json` providers use plain UPPER_CASE env var names (e.g. `"apiKey": "HF_TOKEN"`). The codex provider is special — its `apiKey` is an OAuth binary profile name (`codex-app-server`), not a real secret. OpenClaw's `secrets audit` will always flag it as a provider-specific false positive because codex uses OAuth device code flow. Store OAuth binary names in `gateway.env` for systemd resolution, not via env refs.
- `gateway.env` (loaded by systemd via `EnvironmentFile`) is the KπX-standard location for OpenClaw gateway env vars. It contains actual plaintext API keys. This is by design — systemd `EnvironmentFile` provides process-level isolation. Do not try to move these to OpenClaw's `secrets.providers` unless a specific compaction need arises.
- **OpenCode Web health check with password:** When `OPENCODE_SERVER_PASSWORD` is set, the `/global/health` endpoint returns HTTP 401 (not 200). The systemd `ExecStartPost` health check must accept both 200 and 401: `case "$code" in 200|401) exit 0;; esac`. Without this, the service will fail to start even though opencode is running correctly.
- **Tailscale serve persistence:** Do not use `ExecStopPost` to tear down `tailscale serve` on service stop. If the service crashes and restarts, there's a window where the serve is down and the URL is unreachable. Let the serve persist — it will automatically reconnect when opencode comes back up. The serve config survives service restarts and only needs manual cleanup if you permanently disable the service.
- **2026-07-06 — Whisper model management for @renjfk/opencode-voice:** Models go in `~/.local/share/whisper-cpp/` as `ggml-*.bin` files. The plugin auto-discovers them — no config change needed after adding/removing. Small models are 466MB (same size for EN-only and multilingual — different weights, not compression). Download via `wget` from `https://huggingface.co/ggerganov/whisper.cpp/resolve/main/`. Created `references/voice.md` as single source of truth for all STT/TTS model management documentation.
- **2026-07-22 — OpenCode hooks as file:// plugins (paths updated 2026-08-16):** KπX managed plugins live in `skills/k-opencode/scripts/plugins/hooks/` (helper libs in `scripts/plugins/libs/`) as individual `.js` files, listed in `opencode.jsonc` via `file://` URLs. Plugin array order matters: suggestions-check first → startup-context second. Both use `event: session.created` to capture agent name (info.agent), then conditionally inject on `messages.transform` — only for Colab/Build agents. Post-commit auto-restart must include `scripts/plugins/hooks/*.js` in diff check. Device context injection uses `child_process.execSync("tailscale status --json")` → `assets/infras.json` lookup → read infra skill SKILL.md. If tailscale unavailable, falls back to `os.hostname()`.
- **2026-07-23 — Android/Termux incompatibility confirmed:** The released opencode Linux ARM64 binary is non-PIE (`ET_EXEC`) glibc-linked. Android's `linker64` requires `ET_DYN` (PIE). `termux-elf-cleaner` does NOT fix this — it only adjusts TLS alignment, not `e_type`. The `patchelf` + `glibc-runner` approach also fails because changing the interpreter on a non-PIE binary doesn't make it PIE. Two real fixes: (1) `proot-distro ubuntu` then install inside the proot container (glibc + proot handle PIE), or (2) clone repo and `go build -buildmode=pie` to produce a static PIE binary. Don't waste time on `termux-elf-cleaner` for this — document clearly in the skill.
- **2026-08-04 — Stop-enforcer regression:** The hook code expected `{info, parts}` messages but a recent rewrite queried `session.get()` and then read `sessionObj.messages`, which is always absent. The root fix is `client.session.messages()` plus exact `msg.info.agent` filtering; real OpenCode runs from `/tmp` proved Agent injection and Colab exclusion.
- **2026-08-04 — In-session agent switch:** Matching `info.agent` anywhere in history leaks policy from a prior agent into the current one. Use the shared `agent-scope.js` resolver and only its latest explicit agent; a real Agent → Colab continuation in one session produced two Bash tool parts but only one Agent-owned STOP CHECK text part.
- **2026-08-04 — STOP CHECK false-positive on text-only turns (`ISS-20260804-002`):** `stop-enforcer.js`'s idle guard `if (foundMarker && !usedToolAfterMarker) return;` only suppressed injection when a PRIOR marker existed AND no tool ran since — on the very FIRST idle event of a session (`foundMarker` still `false`), the guard never triggered, so STOP CHECK fired even on pure-text Agent turns with zero tool use, incorrectly preempting normal conversational replies. Root-cause fix: `if (!usedToolAfterMarker) return;` — STOP CHECK now unconditionally REQUIRES a real tool part since the last marker, regardless of whether a marker was ever found. Verified via a deterministic `node --input-type=module` mock harness (2 cases: text-only → 0 injections; post-tool → 1 injection) AND 3 independent live TUI runs (fresh session, same-session Colab→Agent switch, and a 7-agent round-robin after 6 prior switches) — all confirmed via direct `opencode.db` `message`/`part` chronology, not model self-report.
- **2026-08-04 — Exhaustive per-agent hook verification method:** To verify what EACH agent (Colab, Explore, Lite, Build, Plan, Auto, Agent) actually sees/reacts to, do NOT trust a model's own narrated self-report alone — smaller models parrot back literally-quoted marker names from the test prompt itself (false positive), and even capable models (Claude Sonnet 5) can misreport their OWN current identity when asked to compare against a just-prior turn's identity in the same breath (observed: DB-confirmed `agent=Colab` message where the model itself said "I'm currently Plan... not Colab"). The reliable method is: (1) a deterministic `node --input-type=module` harness calling the hook's exported factory directly with synthetic `{info:{role,agent}, parts:[...]}` message arrays, asserting the EXACT injected message set per agent name (proves code-level scoping unconditionally, independent of any LLM); (2) live TUI turns via `tmux send-keys`/`capture-pane` (`opencode` launched bare, `Tab` to cycle agents, `Ctrl+X M` then `Home Enter` to switch away from a stalled default model); (3) cross-checking EVERY live turn against `~/.local/share/opencode/opencode.db` `message`/`part` tables (`role`, `agent`, tool-part presence, exact text) as the ONLY ground truth — never the model's own narration.
- **2026-08-04 — `Auto` agent `"*rm*": "deny"` substring false-positive (`ISS-20260804-003`, reported not fixed — out of this session's hooks-only scope per explicit KπX veto):** OpenCode's `bash` permission patterns glob-match the FULL command string, not the invoked binary token. A leading+trailing wildcard like `"*rm*"` therefore denies ANY command whose text merely contains the two letters "rm" anywhere — including inside unrelated file paths (`auto-rm-probe.txt`) or ordinary English words ("confirm", "term", "warm", "format", "firmware"). The global Zone-4 list already uses the SAFE convention (anchored, start-of-string patterns like `"rm"`, `"rm *"`, `"/usr/bin/rm *"` — matching only commands that literally BEGIN with those tokens); only the `Auto` agent's own permission delta reintroduces an open substring wildcard. Anti-repeat rule: NEVER write a bash permission pattern as `"*token*"` (open substring) when the intent is "block invocations of a specific binary" — always anchor to the start of the command string instead, mirroring the existing Zone-4 examples.
- **2026-08-04 — Frontier models may resist hook-injected enforcement text delivered as `role: "user"` (`ISS-20260804-004`, documented, not redesigned this session):** `agent-lite-enforcement` and `stop-check` are both injected as ordinary `role: "user"` messages (via `appendMessage`/`client.session.prompt`), indistinguishable in role from a real KπX-authored message. Claude Sonnet 5, when it received the Agent-lite block and later the STOP CHECK block, correctly performed the requested benign tool task but explicitly REFUSED the "never ask, never stop" persona framing as a suspected prompt-injection/persona-impersonation attempt — while smaller/less-skeptical models (DeepSeek, Gemini Flash, GPT-5.6 Terra, local qwen2.5) complied without objection in the same testing session. This is a model-capability-dependent limitation of the CURRENT `role: user` delivery channel, not a hook mis-fire (deterministic tests confirm the hook fires exactly as coded in every case). Flag to KπX for a future dedicated decision (accept as-is / change delivery channel / add framing) rather than unilaterally changing the enforcement architecture mid-test.
- **2026-08-09 — OpenCode Web prompt-v2 voice controls:** OpenCode v1.18.15 serves a `form[data-component="prompt-input-v2"]`; its action/control row is the `div.flex.min-w-0.flex-1.items-center.gap-1` ancestor of `[data-action="prompt-attach"]`. Mount injected controls in that row first, then retain the legacy prompt-attach-parent fallback. Verify the compiled `dist/plugin.js` is inline-injected by Lens before Chrome Agent live validation.
- **2026-08-09 — Lens health check logging:** `curl -sf` in `opencode-lens.service` writes the complete injected HTML into the service journal during every restart. Add `-o /dev/null` to its `ExecStartPost` probe so the check remains strict without logging runtime assets.
- **2026-08-16 — Tool-level blocking hook pattern (`make-check-guard.js`):** To enforce a hard kernel rule (GRAVÉ `make check` must run as exactly 2 tokens) at the tool layer, use a `tool.execute.before` hook in an opencode plugin that `throw`s to abort — this is the ONLY reliable block mechanism; mutating `output.args` does NOT propagate (upstream bug opencode #31680). KπX's chosen logic is **ultra-simple on purpose**: find the FIRST `make check` anywhere in the command (no anchoring at start, no unwrapping of `bash -c`/`zsh -c`/multi-line wrappers needed — searching anywhere catches them naturally), then if a blank (whitespace) appears after it → block; otherwise allow. `make check-skills`/`make check-jsonc` stay allowed (followed by `-`, no blank). Accepted false positive: `grep 'make check' file` / `rg "...make check..."` (searching the string) is blocked. Limit: `eval`/base64/script-file still bypass — the hook is a circuit-breaker, NOT an absolute wall; the durable rule remains AGENTS.md + prompts (`prompt-enforcer-strict/lite`). Tests live in `tests/hooks/make-check-guard.test.mjs` (17 cases). Anti-repeat: when blocking bash commands, prefer simple "search token + check what follows" over complex anchored regexes.
- **2026-08-16 — Stateful tmux→agent notification hook (`tmux-notify.js`) — 3 hard-won Node/opencode lessons:** (1) **Reliable persistent-pane completion detection requires GLOBAL `alert-silence` + `monitor-silence`, NOT `pane-died`.** `pane-died` fires only when the pane's shell process exits — it does NOT fire when a command finishes in a persistent pane and returns to the prompt. Per-pane `pane-exited`/`pane-died` is also broken upstream (tmux #2882/#3736). `monitor-silence 2` + the GLOBAL `alert-silence` hook detect "a persistent pane has gone silent = back at its prompt", which matches the KπX workflow (sudo/long commands in persistent panes). Panes stay alive — no `remain-on-exit`, no `bind K kill-pane`. Heuristic caveat: a command that is silent while still running (e.g. `sleep 60` with no output) may be reported done early. (2) **A background watcher must be a RECURSIVE `setTimeout().unref()`, NOT `tail -F` and NOT `setInterval().unref()`.** A spawned `tail -F` keeps the opencode process alive forever (its readable stdout stream stays referenced even with `child.unref()`), hanging `opencode run` on exit. And `setInterval().unref()` re-references itself on every fire, so once it starts polling it also hangs the process. Only `setTimeout()` re-arming itself with `.unref()` on each iteration stays unreferenced across fires. (3) **`client.session.prompt` requires `body.agent`** — without it opencode may ignore the injected prompt (same requirement as `stop-enforcer.js`); resolve the agent via `client.session.messages()` + `agent-scope.currentAgent()`. Also: injected parts MUST carry `synthetic:true` (§6). The relay script writes JSON lines to a log the plugin polls; the shell script uses `flock` for atomic concurrent writes. The `alert-silence` hook's `run-shell` receives session/window/pane context via format expansion (`#{session_name} #{window_index} #{window_name} #{pane_id}`).
