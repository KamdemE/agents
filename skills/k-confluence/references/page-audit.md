# Page Audit

Use this reference when the task is larger than a single page and the documentation must be reviewed as a coherent system.

## Audit Dimensions

Inspect each page across four dimensions:

| Dimension | Questions |
|---|---|
| Narrative | Does the page explain why this section exists and how it connects to the rest? |
| Technical fidelity | Are methods, formulas, variants, and metrics stated accurately? |
| Visual evidence | Are there enough images, plots, examples, and failure cases? |
| Publishing robustness | Do formulas render, links work, and attachments load reliably? |

## Typical Cross-Page Inconsistencies

- Landing page mentions a dataset or method that its dedicated page barely documents.
- Results pages are rich while R&D pages are shallow, hiding the reasoning chain.
- One method page is highly visual while another is mostly text, breaking symmetry.
- Global pages show only one dataset even though two datasets are central.
- Failure analysis exists in local assets but never reaches the online documentation.

## Practical Audit Loop

1. Read the landing page first.
2. Read each child page completely.
3. Compare depth and illustration levels across sibling pages.
4. Identify asymmetries, omissions, and broken rendering.
5. Repair the highest-leverage gaps first.
6. Re-read the landing page to ensure the tree still feels coherent.

## High-Quality Outcome

The best Confluence tree feels like a guided technical exhibition:

- the landing page frames the story,
- each child page earns its existence,
- visuals carry evidence,
- formulas are readable,
- conclusions are justified by the documented path.
