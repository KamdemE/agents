# k-zsh — Insights

Durable, evolutionary lessons for this skill domain. Read before non-trivial work; append at task end.

- **2026-08-24 — curl-installers for language/tool CLIs (`uv`, `bun`, `rustup`, `nvm`, …) self-inject PATH lines into every shell rc file they detect, including the shared `k-zsh` templates:** running the official `uv` and `bun` install scripts on `laptop-wsl` silently appended `. "$HOME/.local/bin/env"` (uv) into `bashrc`/`zshrc`/`profile`, and a `BUN_INSTALL`/PATH block (bun) into `bashrc` — all three are `k-zsh/assets/*` 🔴 NEVER MODIFY files, symlinked and shared across every  infra. Neither installer has any awareness of the `.kshrc` hub pattern; they just grep `$HOME` for known rc filenames and append. Fix: `git diff`/`git status` on `skills/k-zsh/assets/` immediately after running any such installer; revert polluted files with `git checkout --`, then add the equivalent PATH/env line properly (in the one infra `kshrc` that needs it, or `kshrc.base` — see next entry for which). Anti-repeat: treat every curl-pipe-installer as untrusted with respect to shell config — verify what it wrote before trusting a "successfully installed" message.
- **2026-08-24 — `kshrc.base` = COMMON, not "template for future machines":** in the same session, a fix genuinely needed only by `laptop-wsl` (SSH-agent fallback — no `gcr-ssh-agent` on headless WSL) got added to `kshrc.base` too, on the assumption `kshrc.base` was just a seed copied once for *new* infras and safe to enrich freely.  corrected this hard: `kshrc.base` is the live COMMON base — per the file's own 🔴 RED RULE header, any edit to it MUST be propagated to every EXISTING infra `kshrc` copy (list derived from `~/.agents/assets/infras_skills.jsonc`, never hardcoded) in the same change, or not made at all. A speculative `BUN_INSTALL` export was also added without testing — `bun --version`/`bun` worked fine without it (bun defaults to `~/.bun`) — and had to be dropped once actually tested. Both were reverted from `kshrc.base` and every infra copy, kept ONLY in `k-laptop/assets/kshrc` (the one machine that needs the SSH-agent fallback). Anti-repeat: before touching `kshrc.base`, ask (1) is this verified-universal, not assumed? (2) am I propagating it to every infra copy right now, in this same edit? If either answer is no, the change belongs in one infra's `kshrc` only, never in `kshrc.base`. Also: never edit tracked `.agents` skill files with `python`/`sed`/heredoc-in-Bash — use the Edit/Write tools so changes are reviewable and reversible per-hunk; a Bash-script edit is exactly how the base/infra-copy divergence above went unnoticed until  caught it by eye.
- **2026-09-10 — full zsh bootstrap on a fresh Ubuntu workstation (k-ubuntu):** `oh-my-zsh` unattended install writes a template `.zshrc` into `$HOME`; overwrite-guard it by symlinking the 5 frozen `k-zsh/assets/*` files across it with `ln -sf` immediately after. The 3 custom plugins must be cloned into `~/.oh-my-zsh/custom/plugins/` (not `plugins/`) or omz won't load them. Validate end-to-end with `zsh -i -c 'echo $ZSH_VERSION; echo ${#plugins}' </dev/null` (non-TTY still runs interactive init). `chsh -s` needs the user's password — an agent shell cannot do it (`PAM: Authentication failure`); hand it to the human (or tmux gate). Removing the auto-cd-to-`~/Labs` from `kshrc.base` required the same fleet-wide propagation (all 7 infra copies edited in the same shot) because it lives inside the shared `__KSHRC_INTERACTIVE_LOADED` block; the `~k`/`~e`/`~a`/`~d` `hash -d` shortcuts and `$KHOME`/`$AGENTS` vars survive untouched.
