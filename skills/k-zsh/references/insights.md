# k-zsh — Insights

Durable, evolutionary lessons for this skill domain. Read before non-trivial work; append at task end.

- **2026-08-24 — curl-installers for language/tool CLIs (`uv`, `bun`, `rustup`, `nvm`, …) self-inject PATH lines into every shell rc file they detect, including the shared `k-zsh` templates:** running the official `uv` and `bun` install scripts on `blglaptop139-wsl` silently appended `. "$HOME/.local/bin/env"` (uv) into `bashrc`/`zshrc`/`profile`, and a `BUN_INSTALL`/PATH block (bun) into `bashrc` — all three are `k-zsh/assets/*` 🔴 NEVER MODIFY files, symlinked and shared across every KπX infra. Neither installer has any awareness of the `.kshrc` hub pattern; they just grep `$HOME` for known rc filenames and append. Fix: `git diff`/`git status` on `skills/k-zsh/assets/` immediately after running any such installer; revert polluted files with `git checkout --`, then add the equivalent PATH/env line properly (in the one infra `kshrc` that needs it, or `kshrc.base` — see next entry for which). Anti-repeat: treat every curl-pipe-installer as untrusted with respect to shell config — verify what it wrote before trusting a "successfully installed" message.
- **2026-08-24 — `kshrc.base` = COMMON, not "template for future machines":** in the same session, a fix genuinely needed only by `blglaptop139-wsl` (SSH-agent fallback — no `gcr-ssh-agent` on headless WSL) got added to `kshrc.base` too, on the assumption `kshrc.base` was just a seed copied once for *new* infras and safe to enrich freely. KπX corrected this hard: `kshrc.base` is the live COMMON base — per the file's own 🔴 RED RULE header, any edit to it MUST be propagated to every EXISTING infra `kshrc` copy (list derived from `~/.agents/assets/infras_skills.jsonc`, never hardcoded) in the same change, or not made at all. A speculative `BUN_INSTALL` export was also added without testing — `bun --version`/`bun` worked fine without it (bun defaults to `~/.bun`) — and had to be dropped once actually tested. Both were reverted from `kshrc.base` and every infra copy, kept ONLY in `k-blglaptop139/assets/kshrc` (the one machine that needs the SSH-agent fallback). Anti-repeat: before touching `kshrc.base`, ask (1) is this verified-universal, not assumed? (2) am I propagating it to every infra copy right now, in this same edit? If either answer is no, the change belongs in one infra's `kshrc` only, never in `kshrc.base`. Also: never edit tracked `.agents` skill files with `python`/`sed`/heredoc-in-Bash — use the Edit/Write tools so changes are reviewable and reversible per-hunk; a Bash-script edit is exactly how the base/infra-copy divergence above went unnoticed until KπX caught it by eye.
